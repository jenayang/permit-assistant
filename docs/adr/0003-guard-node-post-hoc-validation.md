# ADR-0003: 프롬프트 지시만으로 부족해 `guard_node`로 답변을 사후 검증한다

## Status

Accepted

> 소급 작성 ADR — 2026-07-26 결정 당시 근거를 `docs/project_report.md` 4-3,
> `docs/memory/guard-node-pattern.md`, 커밋 `5cc8cac`를 바탕으로 재구성함.
> 이 프로젝트에서 "가장 중요한 아키텍처 전환점"으로 기록된 결정.

---

## Context

LLM이 자유 텍스트로 답변을 끝낼 때, 시스템 프롬프트에 아무리 지시를 강화해도
막히지 않는 사고가 반복됐다.

- 현재 상황: 2026-07-24 dev log에 이미 "시스템 프롬프트에 지시를 강화했는데도
  시설군 누락이 재현된다 - 근본적으로는 LLM 신뢰성 이슈"라고 기록돼 있었다.
- 해결해야 하는 문제: 2026-07-26 세션에서 판정 직후 LLM이 여러 단계를 한
  메시지에 몰아 공개하고, 사용자가 범위를 명시해도 무시하는 사고가 실측으로
  재현됐다. 근거 없는 법령 인용, 판정 전 단계 안내 등도 같은 성격의 문제였다.
- 제약: 이 프로젝트의 핵심 가치는 "신뢰할 수 있는 안내"다 — 근거 없는 법령
  인용이나 순서를 건너뛴 안내는 사용자가 실제로 잘못된 절차를 밟게 만들 수 있다.

---

## Decision Drivers

- ADR-0001과 같은 원칙: 안전-critical한 지점은 확률적 컴포넌트(LLM)에만
  맡기지 않는다.
- 프롬프트 수정은 비용이 낮지만, 이미 "지시 강화 → 같은 사고 재현"이 반복
  확인된 상태라 신뢰할 수 없는 해법이다.
- 무한 재시도로 인한 응답 지연ᆞ사용자 경험 저하는 피해야 한다.

---

## Considered Options

### 1. 시스템 프롬프트를 계속 더 길게ᆞ강하게 작성

위반 사례가 발견될 때마다 "이러지 마라"는 지시를 프롬프트에 추가하는 방식.

**장점**
- 그래프 구조를 안 건드리므로 구현이 빠르다.
- 코드 변경 없이 즉시 적용된다.

**단점**
- 이미 "지시를 강화했는데도 재현된다"가 두 차례(시설군 누락, 단계 몰아주기)
  확인된 전례가 있다 — 근본적으로 신뢰할 수 없는 해법.
- 프롬프트가 계속 길어져 토큰 비용ᆞ"lost in the middle" 위험이 커진다
  (ADR-0010ᆞADR-0011에서 실제로 이 비용이 측정됨).

### 2. 그래프 레벨에서 자유 텍스트 답변을 사후 검증하는 노드 추가

LLM이 자유 텍스트로 턴을 끝내려 할 때, 정규식+상태로 결정론적으로 검증하는
`guard_node`를 그래프에 추가하고, 위반 시 같은 턴 내에서 재시도시키는 방식.

**장점**
- ADR-0001의 `classify_case`와 같은 논리를 대화 품질 검증에도 적용 — 코드가
  확정적으로 잡아낸다.
- 위반 유형별로 체크를 독립적으로 추가ᆞ확장할 수 있다(실제로 2개→6개로 확장).

**단점**
- 매 턴 정규식 기반 검증 오버헤드(경미).
- 위반 감지 시 LLM 재호출 1회가 추가돼 응답 지연이 생긴다.
- 체크를 "실측으로 확인된 사고"에 맞춰 좁게 설계하면 커버리지가 의도적으로
  불균등해진다(아래 Negative 참고).

---

## Decision

**그래프 레벨에서 자유 텍스트 답변을 사후 검증하는 `guard_node`를 도입한다.**

선택 이유: "프롬프트 지시만으로는 못 막는다"가 반복적으로 실측 확인됐다.
ADR-0001에서 판정을 코드로 뺀 것과 같은 논리를 대화 품질 검증에도 적용하는
것이 유일하게 신뢰할 수 있는 해법이었다.

- 같은 턴 최대 1회 재시도로 제한해 무한 루프를 방지한다.
- 위반 체크는 실측으로 확인된 사고에 맞춰 하나씩 추가한다(2개→5개→6개로 확장,
  이후 7개까지 — ADR-0006).

---

## Consequences

### Positive

- 근거 없는 법령 인용, 판정 전 단계 안내, 한 턴에 여러 단계 몰아주기, 기록
  누락 등 실제로 재현됐던 사고를 코드 레벨에서 확정적으로 잡아낸다.
- 위반 체크가 독립적으로 늘어날 수 있는 확장 가능한 구조라, 이후 발견되는
  새 사고 유형(ADR-0006의 RAG 활용도 저조 등)도 같은 틀 안에서 추가됐다.

### Negative

- 이 프로젝트의 "실측 기반으로만 좁게 고친다" 원칙 때문에 체크 커버리지가
  의도적으로 불균등하다 — 예를 들어 인용 검증(체크②)은 "대화 전체에 검색이
  한 번이라도 있었는지"만 보고 최신성은 따지지 않아, 훨씬 이전 턴의 근거로
  나중 턴의 무관한 인용까지 통과되는 한계가 있다(`phase1_roadmap.md`에 알려진
  한계로 명시, 2026-07-29 기준 의도적 보류).
- 위반 감지 시 LLM 재호출 1회로 응답 지연이 추가된다.

---

## Reconsideration Conditions

- 인용 검증의 최신성 창 문제(이전 턴 근거로 무관한 인용이 통과되는 경우)가
  실제 오안내 사례로 관측되면, 체크②를 최신성 기준으로 강화하는 걸 재검토한다.
- 위반 체크 수가 늘어나 정규식 기반 검증 자체의 유지보수 비용이 과도해지면
  (현재 7개), 체크 구조를 테이블화ᆞ선언적으로 재설계하는 걸 검토할 수 있다.
