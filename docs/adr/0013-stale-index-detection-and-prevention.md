# ADR-0013: "컨텍스트 문제"로 보였던 것의 실제 원인은 인덱스 미갱신이었다 — 시작 시 경고로 재발을 방지한다

## Status

Accepted

> 소급 작성 ADR — 2026-08-02 결정 당시 근거를 `docs/project_report.md` 4-13,
> 커밋 `01e0eed`ᆞ`013bc26`를 바탕으로 재구성함.

---

## Context

ADR-0010에서 Cerebras 폴백 한도(131,072) 대비 컨텍스트 사용량이 92%
(120,903토큰)로 나와 트리밍ᆞ요약 같은 설계를 검토하려던 참이었다.

- 현재 상황: 그 전에 "가이드 도구 출력 86,974토큰(전체의 72%)이 대체 뭘로
  채워져 있나"를 실제로 열어봤는데, `get_business_registration_guide`
  (사업자등록 = 부가가치세법 소관)가 **식품위생법 제43조의3**(공유주방
  등록사항 변경)을 반환하고 있었다 — 완전히 무관한 조문이다.
- 해결해야 하는 문제(원인): `data/laws/`에는 부가가치세법ᆞ국민연금법ᆞ
  국민건강보험법ᆞ고용보험법ᆞ옥외광고물법ᆞ다중이용업소법이 있는데 벡터DB엔
  0청크였다(18종만 인덱싱된 상태) — 법령을 추가하고 재인덱싱을 하지 않은
  것이다.
- 핵심 통찰: 검색은 실패하지 않는다 — 없으면 "가장 비슷한" 무관한 조문을
  조용히 돌려준다. 그래서 답변은 그럴듯한데 근거만 틀린 상태로 운영되고
  있었고, 아무도 눈치채지 못했다.

---

## Decision Drivers

- "컨텍스트가 부족하다"는 겉보기 문제를 그대로 믿지 않고, 실제 내용을
  열어서 확인한다 — 이 프로젝트에서 "A로 보였는데 실은 B였다"가 이 세션에서
  벌써 세 번째였다(ADR-0012의 tool-calling 스킵, 타입 강제 변환, 그리고
  이번 건).
- 같은 사고가 재발하지 않도록 구조적 안전망(시작 시 경고)을 둔다.
- 서버 기동 자체를 막아서는 안 된다 — 일부 파일이 미인덱싱이어도 나머지는
  정상 동작해야 한다.

---

## Considered Options

### 1. 트리밍ᆞ요약 설계로 바로 진행

컨텍스트 사용량 92%라는 수치를 그대로 받아들이고, ADR-0009에서 반증됐던
트리밍이나 새로운 요약 설계를 다시 검토하는 방향.

**장점**
- 수치상 즉각적인 문제(한도 근접)에 바로 대응하는 것처럼 보인다.

**단점**
- 근본 원인(틀린 근거로 답변하고 있었다는 것)을 전혀 건드리지 못한다 —
  며칠을 써서 트리밍ᆞ요약을 설계해도 "컨텍스트가 큰 이유"가 해결되지
  않은 채 남는다.

### 2. 실제 반환값을 열어서 원인을 먼저 확인

컨텍스트를 줄이기 전에, 가이드 도구가 실제로 무엇을 반환하는지 직접 열어
확인하는 방향.

**장점**
- 실제 원인(인덱스 미갱신으로 무관한 조문 반환)을 찾아내, 트리밍 없이도
  컨텍스트 사용량을 33% 줄이고 동시에 답변 정확성까지 고쳤다.

**단점**
- 원인 조사 자체에 시간이 든다(다만 이번 사례는 빠르게 발견됨).

---

## Decision

**재인덱싱으로 근본 원인을 해결하고, 재발 방지를 위해 `find_unindexed_sources()`
와 서버 시작 시 경고(`_warn_if_index_stale`)를 추가한다.**

선택 이유: "컨텍스트가 부족하다"는 문제로 보였던 것의 상당 부분이 실은
검색 품질 문제였다. 트리밍ᆞ요약 설계로 바로 갔다면 며칠을 쓰고도 근본
원인(틀린 근거로 답변)은 그대로 남았을 것이다.

- 증분 인덱싱으로 1,290청크 추가(2,157 → 3,447, 기존은 재임베딩 없이
  스킵).
- 재발 방지는 서버 기동을 막지 않는 경고 방식으로 설계했다 — 일부 파일이
  빠져도 나머지는 정상 동작하고, `hwp5html` 미설치 환경처럼 일부 포맷을
  못 읽는 경우까지 서버를 못 뜨게 하면 과하다.

---

## Consequences

### Positive

- 재인덱싱 효과(실측): 무관한 조문을 반환하던 두 가이드(`get_opening_checklist`
  -62%, `get_business_registration_guide` -31%)가 정확히 줄었고, 원래
  정상이던 두 가이드는 변화가 없었다 — 예상과 일치하는 결과라 신뢰할 만하다.
  합계 86,974 → **57,927토큰(-33%)**.
- 컨텍스트 여유: 로드맵 완주 누적 120,903 → **91,856토큰**. Cerebras 한도
  대비 **92% → 70%**(여유 10,169 → 39,216).
- 답변 정확성이 동시에 개선됐다 — 컨텍스트 절감과 근거 정확성이 같은
  원인 해결에서 함께 나온 결과.

### Negative

- 현재 환경에서 `.hwp` 별표 11건(주차장 설치기준ᆞ옥외광고물 수수료 등)이
  여전히 미인덱싱으로 잡힌다 — 실제로 근거가 빠진 상태가 맞으므로 경고를
  유지하지만, 완전히 해소된 건 아니다.
- 경고가 서버 기동을 막지 않으므로, 로그를 확인하지 않으면 여전히 놓칠 수
  있다(사람이 로그를 봐야 하는 안전망의 한계).

---

## Reconsideration Conditions

- 70%도 트리밍을 정당화하기엔 근거가 약하다고 보고 당장은 도입하지 않았다
  (ADR-0009의 롤백 이력 때문에 더 신중하게 판단) — 여유가 다시 줄어들면
  ADR-0014의 관측 데이터를 근거로 재검토한다.
- `.hwp` 미인덱싱 11건이 실제 답변 품질 문제로 이어지는 사례가 관측되면,
  `hwp5html` 의존성 설치를 배포 필수 조건으로 격상하는 걸 검토한다.
- 경고만으로 충분하지 않다고 판단되면(사람이 로그를 놓치는 사례가 반복되면),
  기동을 막는 더 강한 안전장치로 격상하는 걸 재검토한다.
