# 로드맵 역할ᆞ순서ᆞ분기 재설계 (Step 0~2)

## Context

세션 2faaacad/3d2f20a1 이후 실사용 중 사용자가 4개의 개별 버그를 신고했다:

1. 소방시설이 Step3(창업 행정)에 있는데, 실제로는 사용자가 별도로 하는 일이 아니라 시공의 일부가 아닌지.
2. Step1-2(사전 검토) 전에 건축사사무소 선정이 먼저 와야 하는 것 아닌지, 선정이 의무가 아닐 때 직접/대행 분기가 있어야 하고 서류도 "건축주 준비 vs 건축사사무소 준비"로 명확히 나뉘어야 하는 것 아닌지.
3. 1-2 확인 없이 1-3으로 넘어가는 버그(이미 하드 게이트로 1차 수정했으나, 마커가 없으면 여전히 새는 사례 발견).
4. 시공+인테리어를 다 하는 경우와 인테리어만 하는 경우를 구분해서 시공 항목을 닫아야 하는 것 아닌지.

조사해보니 4개 모두 같은 뿌리를 공유한다 - **"이 절차를 누가 하는지ᆞ언제 확정돼야 하는지ᆞ이 케이스에 실제로 해당하는지"라는 축이 로드맵 구조에 없다.** 개별 패치 대신 Step 0~2 구조를 한 번에 재배치한다.

이 문서는 지난 세션에 이미 구현ᆞ커밋된 Step1(4단계)ᆞStep2(3단계) 구조를 되돌리는 게 아니라, 그 위에 역할ᆞ분기 축을 추가하는 재배치다.

## 결정된 사항

### 1. Step 0 확장 (판정을 Step0으로)

`case_facts._classified`(허가/신고/기재변경/불필요 판정)는 사실이 모이면 코드가 즉시 계산하는 결과라 페이싱이 필요 없다. 지금은 이게 Step1의 첫 하위단계 `[Step 1-1: 대상 판정]`로 묶여 있는데, Step0(행위 유형 확인)과 합쳐 **Step0에서 즉시 노출**한다.

### 2. 건축사사무소 선정 = 새 Step1-1

Step1-3(설계ᆞ서류 준비)이 실제로 설계도서를 만들려면 그 전에 건축사가 정해져야 한다. 지금 Step2-1(착공 직전)에 있는 건축사 선정 문구를 제거하고, **새 `[Step 1-1: 건축사사무소 선정]`**으로 옮긴다. 이후 1-2ᆞ1-3ᆞ1-4는 순서 그대로(사전검토ᆞ설계서류ᆞ신청접수) - `_STAGE_MARKER_LINE_PATTERN`(`[Step 1-1]`~`[Step 1-4]`) 정규식ᆞ4단계 구조 자체는 안 바뀌고, 각 번호가 가리키는 **내용**만 재배치된다(1-1의 의미가 "대상판정"→"건축사선정"으로 바뀜).

`requires_licensed_architect` 판정에 따라:
- **True(의무)**: "선정하셔야 합니다" 안내 → "선정하셨어요?" 확인(`architect_selected`) 통과해야 1-2로.
- **False(선택)**: "직접 하실 건가요, 대행업체(건축사사무소ᆞ행정사) 도움을 받으실 건가요?" 질문 → `uses_agency`(bool)로 기록.
  - 대행 선택 시: "그 업체는 선정하셨어요?"(`architect_selected`)까지 확인돼야 1-2로.
  - 직접 선택 시: 선정할 대상이 없으니 게이트 즉시 통과.
  - 미결정이면 1-2로 못 감.
- **None(정보 부족)**: 안내 생략, 게이트 없음(막지 않음).

### 3. 직접/대행에 따른 서류 역할 재정비 (Step1-3)

`search_regulations`로 확인한 결과, 법조문(건축법 시행규칙 제12조의2 등)은 "신청서를 제출하는 자"(법적 명의자 = 항상 건축주)만 규정하고 "누가 실제로 작성하는지"는 명시하지 않는다 - 즉 "건축사사무소가 대행해준다"는 실무 관행이지 법적 요건이 아니다. 지금 프롬프트의 [본인 준비]/[설계자 준비] 2분류가 이 둘을 뭉개고 있었다.

Step1-3의 서류 목록을 다음 기준으로 재정비:
- **법적 명의자**: 항상 건축주(변하지 않음, 별도 표기 불필요하거나 참고용으로만).
- **실제 작성 주체**: `uses_agency`가 True면 "대행업체가 작성, 건축주는 서명ᆞ제출만", False(직접)면 "본인이 직접 작성ᆞ제출". 순수 설계 영역(도면 등, 건축사 의무 시 항상 건축사 소관)은 별도 유지.

### 4. 소방시설 = Step2 소속

`search_regulations`로 확인: 실제 설치는 소방시설공사업법상 별도 면허를 가진 "소방시설공사업자"(일반 시공사와 다른 전문 업체)가 한다. 건축허가 시 소방서 동의, 사용승인 시 "소방시설공사의 완공검사증명서"로 갈음 - 관공서 간 처리라 사용자가 직접 챙길 일은 없되, **완공검사증명서 발급 자체는 챙겨야 하는 서류**(대행업체 안 쓰면 사용자가 직접 소방서에 신청해서 받아야 사용승인 신청에 첨부 가능).

Step3(창업 행정)에 있던 소방시설 항목을 **Step2-2(시공ᆞ공사감리ᆞ소방시설ᆞ인테리어ᆞ장비 설치)**로 이동. 판정(fire_result)은 여전히 아무 때나 계산되지만 UI 표시 위치만 이동. Step4 "영업 시작" 게이트(`step3AllDone`)에서 소방 항목 제외 필요(Step2 완료에 이미 포함되므로 이중 게이트 방지).

### 5. 시공 항목 N/A 조건 확장 (구조공사 vs 인테리어만)

지금은 `permitNotNeeded`(일반수선 등 인허가 자체가 불필요한 경우)일 때만 시공 항목이 사실상 의미 없어지는데, 용도변경처럼 **허가/신고 대상이어도 실제 구조 공사 없이 인테리어만 진행하는 케이스**가 있을 수 있다.

Step2-1(착공신고)에서 "구조 공사(신축ᆞ증축ᆞ대수선 등)도 하시나요, 인테리어만 진행하시나요?" 질문 추가 → 인테리어만이면 `construction_notice`/`construction`을 notApplicable 처리. `permitNotNeeded` 케이스는 자동으로 N/A, 그 외(허가/신고 대상)는 이 질문으로 확인.

### 6. 게이트 신뢰성 보강 (마커 없이 새는 문제)

오늘 스모크 테스트로 확인: LLM이 `[Step 1-N]` 대괄호 헤더 없이 서술형으로만 다음 단계 내용을 전달하면 `_mentioned_stages` 기반 하드 캡이 아예 못 잡는다(1차 수정에서 하드 게이트를 추가했지만, 이 게이트도 마커 탐지에 의존해서 같은 사각지대가 있음).

**해결책**: 텍스트 마커 대신 **툴 호출 자체**를 "그 단계 내용이 실제로 전달됐다"는 신호로 쓴다 - `record_permit_synthesis(required_documents=[...])`가 이번 턴에 호출되려는데 앞 단계 확인 게이트(`pre_diagnosis_checked` 등)가 안 풀려 있으면 위반으로 잡는다. 툴 호출은 구조적으로 항상 검사 가능해서 텍스트 서식에 좌우되지 않는다.

## 새 상태 필드 (`task_progress`)

`hires_staff`와 같은 선례(완료 여부가 아니라 "선택ᆞ해당 여부"를 담는 패턴)를 따른다:

- `uses_agency: bool | None` - 건축사 선택제일 때 직접/대행 여부.
- `architect_selected: bool` - 건축사(또는 대행업체) 실제 선정 완료.
- `interior_only: bool | None` - Step2-1에서 "구조공사 없음"으로 답하면 True.

## 영향받는 파일

- `src/roadmap.py` - Step0/1 마커 의미 재배치(`_STAGE_MARKER_LINE_PATTERN`의 1-1이 이제 "건축사 선정"), `_pending_stage1_confirmation`에 건축사 게이트 추가, 툴 호출 기반 위반 신호로 전환.
- `src/prompts.py` - `_ANSWER_PERMIT_STAGES` 전면 재작성(1-1~1-4 내용 재배치), Step1-3 역할 표기 로직 교체.
- `src/agents/construction.py` - Step2-1에서 건축사 문구 제거, 구조공사 여부 질문 추가, Step2-2에 소방시설 안내 편입.
- `src/agents/roadmap_progress.py` - `uses_agency`ᆞ`architect_selected`ᆞ`interior_only` 필드 추가.
- `src/guard.py` - 툴 호출 기반 새 위반 체크, 마커 재배치에 따른 기존 검증 갱신.
- `src/project_status.py`, `src/static/index.html` - Step0 substep에 판정 결과 추가("행위 유형 확인" 하나뿐이던 걸 "행위 유형+대상 판정" 2개로), Step2/3 항목 재배치(소방시설 이동, 시공 N/A 조건), Step4 게이트 조정.
- `tests/test_agent_guard.py`, `tests/test_roadmap_locks.py` - 마커 의미가 바뀌므로 대량 갱신 필요.

## 테스트/검증 방향

- 기존 순차 진행 테스트(`test_sequential_walkthrough_then_construction_transition`류)를 새 단계 순서(1-1 건축사선정→1-2 사전검토→1-3 설계서류→1-4 신청접수)로 재작성.
- 직접/대행 분기별 게이트 통과 시나리오(대행+미선정=차단, 직접=즉시 통과) 신규 테스트.
- 인테리어 전용 케이스에서 시공 항목 N/A 처리 JS 하네스 테스트 추가(`roadmap_locks_check.js` 패턴).
- 툴 호출 기반 위반 체크: `record_permit_synthesis` 호출 시점에 앞 게이트 미충족이면 재시도 유도되는지 단위 테스트.
- `uv run pytest` 전체 통과 + 실제 LLM 스모크 테스트(건축사 의무/선택 케이스 각 1회, 인테리어 전용 케이스 1회) - 유닛 테스트만으로 완료 보고하지 않는다(CLAUDE.md §3).
