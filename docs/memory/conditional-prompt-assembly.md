# 조건부 프롬프트 조립 — 도메인 블록을 상태에 따라 켜고 끄기

**원칙**: `SYSTEM_PROMPT`를 블록 상수로 쪼개고 `build_system_prompt(state)`가
매 턴 필요한 블록만 조립한다(`agent.py`). 간판만 묻는 턴에 식품ᆞ소방 규칙
전체를 매번 읽힐 이유가 없다는 실측(`## 1. 정보 수집`이 전체의 44%)에서
시작.

**점등 조건은 느슨한 OR**: ① 도메인이 이미 상태에 살아있음 ② 대화
전체에서 그 도메인 키워드가 한 번이라도 등장. **한 번 켜지면 대화 끝까지
유지** — 매 턴 재평가하면 도구 스킵 한 번에 블록이 꺼져 판정이 조용히
실패할 수 있다(실제로 겪음, `_all_human_text`로 전체 스캔하도록 고쳐 해결).

**의도적으로 느슨하게 잡은 이유**: 꺼야 할 블록을 켜두는 비용은 토큰 몇
백이지만, 켜야 할 블록을 끄면 판정 자체가 조용히 실패하는 비대칭 리스크.

**효과**: 평균 17.6%~18.7% 절감(시나리오별 0%~62%, 간판 전용 대화가 최대).
전체 로드맵 진행 중인 후반부는 0%에 수렴 — 이 조치는 [[context-budget-management]]의
Cerebras 한도 문제를 해결하지 못한다(가이드 도구 누적이 지배적 원인).

**실측으로만 잡히는 회귀 조심**: 유닛 테스트를 다 통과해도 "도메인 무관한
공통 원칙이 특정 도메인 블록 안에 묻혀 있어서 그 블록이 꺼지면 같이
사라지는" 버그는 실제 LLM 호출로만 드러났다. 공통 원칙은 항상 켜지는
`_COLLECT_COMMON`류 블록에 둘 것.
