# Rule Justification — 판정 사유도 코드가 만든다

**원칙**: "왜 이 판정인가"를 LLM이 즉흥적으로 설명하게 하지 않고, 규칙
자체가 결정론적 사유 문장을 만들어 도구 응답에 실어보낸다. RAG 검색 없이
근거가 붙는다는 게 핵심(근거의 결정론성).

**왜**: 용도변경 방향(시설군 이동) 오판 사고 이후 그 도메인에만
`_facility_group_reason()`을 붙였는데, 나머지 act_type은 여전히 LLM이
"왜"를 즉흥 설명해야 했다 — 비대칭이 위험 요인.

**구현**: `permit.py`의 `_act_type_reason()`(9개 act_type 전체),
`food_safety.py`의 `_FOOD_BUSINESS_RULE`(판정→조문ᆞ사유 매핑). 새 판정
도메인을 추가하거나 사유가 미묘한 케이스가 생기면 이 패턴을 재사용할 것.

**유지보수 리스크**: 사유 문장의 비교 조건이 `classify_*()`의 실제 판정
조건과 별도 위치에서 재비교되는 구조라, 법정 임계값이 아닌 **조건 구조
자체**가 바뀌면 두 곳을 같이 고쳐야 한다(숫자만 바뀌는 개정은
`get_thresholds()` 공유로 안전).
