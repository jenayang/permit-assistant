# tool-calling 신뢰성 (해결됨)

**결론**: 원인은 대화 길이도 프롬프트 표현도 아니라, 모델이 도구를 "필수"가
아니라 "권장"으로 다루는 **도구 선택 층위** 문제였다. `tool_choice` API
강제로 실측 0%→100% 해결.

**기각된 가설**(재검토 불필요): 대화 길이(트리밍 A/B 실측 무차이) · 도구
개수(signage는 통했지만 food는 안 통함, 부분적) · 질문형 어미(서술문도
스킵됨).

**측정 함정(중요)**: `pipeline.query()`로 재면 안 됨 — guard 재시도가
2번째 시도에서 성공하면 마치 정상인 것처럼 보인다. 반드시
`llm.bind_tools(tool_choice=...).invoke([...])` **직접 1회** 호출로 격리.
(CLAUDE.md §4 참고 — 여기가 원본 배경)

**해결책**: `_forced_record_tool`로 전 도메인 강제. 조건 3가지: ① facts
완전히 비었을 때만 ② 이번 턴에 아직 안 불렸을 때만 ③ 정의성 질문 제외.

**설계 경계(테스트로 고정)**: **기록은 강제, 검색은 모델 판단.** 검색까지
강제하면 맥락 의존적 판단을 과도하게 규칙화하게 됨. 예외:
`get_construction_guide`(로드맵 진행 규칙이라 성격이 다름).

**남는 한계**: 키워드 없이 사실만 흘리는 발화는 여전히 모델 재량. 호출은
보장하나 추출 품질은 별도 과제(Gold Set으로 측정 중).
