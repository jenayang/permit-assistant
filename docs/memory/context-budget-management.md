# 컨텍스트 예산 관리

**교훈**: "컨텍스트 부족"처럼 보인 문제의 상당 부분이 실은 **인덱스 미갱신
(검색 품질)** 문제였다. 큰 설계(트리밍ᆞ요약)부터 가지 말고 항상
**관측 → 원인 분리 → 필요한 만큼만 개입** 순서.

**실측 결과**: 시스템 프롬프트+도구 정의로 매 턴 18,223토큰 고정, 가이드
도구 4개 누적 81,288토큰. Gemini 1,048,576토큰(여유 큼) vs Cerebras 폴백
131,072토큰(위험).

**진짜 원인 발견**: 가이드 도구 출력을 열어보니 완전히 무관한 조문을
반환 중 — 법령 파일은 추가했는데 재인덱싱을 안 해서 벡터DB엔 0청크였다.
**검색은 실패하지 않는다 — 없으면 "가장 비슷한" 무관한 조문을 조용히
돌려준다.** 재인덱싱 후 출력 -33%, 한도 대비 92%→70%.
→ `find_unindexed_sources()`가 서버 시작 시 자동 경고.

**그래도 필요했던 안전망**: 관측(`_log_context_usage`, 75% 넘으면 WARNING,
차단 안 함) 먼저 깔고, 이후 자동 절삭(80% 넘을 때만, LLM 전달 **사본만**
절삭ᆞ원본 보존, `trim_messages` 사용).

**롤백된 트리밍(4-9)과 다른 점**: 트리거가 "항상"이 아니라 "80% 넘을 때만"
(평소 대화는 2~3%라 사실상 안 켜짐). 목적도 tool-calling 개선(증명 실패)이
아니라 하드 에러 방지(원인 명확).

**요약(summarization) 채택 안 함**: 법령 근거를 요약하면 조문 번호가
뭉개진다 — 자르는 게 요약보다 안전(틀리게 남기지 않음).
