## 오늘의 핵심 교훈 — "A로 보였는데 실은 B였다"가 다섯 번

고치기 전에 실측하는 습관이 매번 값을 했다. 추측대로 갔으면 전부 엉뚱한 곳을
고쳤을 것이다.

| 겉보기 문제 | 실제 원인 |
|---|---|
| 대화가 길어서 tool-calling 스킵 | 모델이 도구를 **선택 사항**으로 취급(첫 턴에서도 재현) |
| 폴백 모델의 추출 능력 부족 | **JSON 타입 차이**(값은 100% 정확했음) |
| 가이드가 컨텍스트를 많이 먹음 | **인덱스 미갱신**으로 무관한 문서를 긁어옴 |
| hwp5html 미설치 | **PATH 해석** 문제(설치는 되어 있었음) |
| 간판 부가 필드 추출 실패 | **Gold Set(정답지)이 틀림** — 모델이 옳았음 |

특히 세 번째는 트리밍 설계로 바로 갔으면 며칠 쓰고도 근본 원인(틀린 근거로 답변)은
그대로 남았을 것이다.

**측정 함정 하나 기록**: tool-calling 호출률을 `pipeline.query()`로 재면 안 된다.
그건 도구 루프ᆞclassifyᆞ**guard 재시도**까지 도는 경로라, guard가 다른 이유로
재시도를 걸면 두 번째 시도에서 도구가 불려 **성공한 것처럼 보인다**. 이 착시로
하루치 관측을 헛짚었다. `llm.bind_tools(...).invoke()`를 직접 1회 호출해 격리할 것.

### 1. [결정 필요] `sells_ready_made_only`의 법령 해석 ⭐ 최우선

**혼자 판단하지 말고 사용자 확인 후 진행할 것.** 규칙 엔진이 법령과 어긋나 보인다:

```python
# src/agents/food_safety.py
if facts.get("sells_ready_made_only"):   # "조리 없이 완제품만 판매"
    return "즉석판매제조가공업"            # ← 제조ᆞ가공하는 영업
```

원문(식품위생법 시행령 제21조2호): *"즉석판매제조ᆞ가공업: 총리령으로 정하는 식품을
**제조ᆞ가공업소에서** 직접 최종소비자에게 판매하는 영업"*. 고시 별표12의 예시는
**반찬ᆞ죽ᆞ떡가게** — 전부 업소에서 만들어 파는 곳이다.

즉 "조리 안 하고 완제품만 판매"는 제조ᆞ가공을 안 하므로 이 업종이 아닌 것으로
보인다. 제21조5호 **식품소분ᆞ판매업**이 더 맞아 보이고, 그것도 제25조상 신고
대상인데 현재 규칙 엔진엔 이 업종 자체가 없다.

선택지: ① 식품소분ᆞ판매업을 추가 ② 이 필드를 재정의 ③ 위 해석이 틀렸는지 재확인.
**판정 규칙 변경은 사용자 결정 사항**이다([[feedback_permit_rule_engine]] 원칙).

관련: Gemini가 이 필드를 반복적으로 못 뽑는데(0~1/4), 필드 의미가 법령과 어긋난 게
원인일 가능성이 있다 — 의미를 바로잡은 뒤 재측정하면 갈린다.

### 3. 컨텍스트 — 로그 보고 판단

`[CONTEXT]` 경고가 실제로 자주 찍히는지 관찰. 로드맵을 끝까지 밟는 대화를 몇 번
해보면 실제 값이 보인다(방금 짧은 대화는 2~3%였다).
- 80~90%가 자주 나오면 → 요약(summarization) 검토
- 20~30%에 머물면 → 지금 상태 유지

**요약은 신중할 것**: 법령 근거를 요약하면 조문 번호가 뭉개진다. 자르는 건
"없어지는" 거고 요약은 "틀리게 남는" 거라 성격이 다르다.

### 4. 그 외 미착수

- Answer 블록 도메인 분리 — 식품ᆞ소방ᆞ간판 전용 답변 규칙이 아직 안 쓰여서 나눌
  재료가 없다. 그 내용이 생기면 그때.
- `prompts/*.md` 파일 분리 — 검토 후 보류. 프롬프트가 `agent.py`의 14%뿐이고, 규칙과
  근거 주석이 갈라지는 비용이 diff 가독성 이득보다 크다고 판단.
- 복합 행위 케이스(증축+용도변경) — `act_type`이 단일 필드라 표현 불가. 실사용
  데이터를 보고 판단.

## 새 환경 세팅 (다른 컴퓨터에서 시작할 때)

`.env`ᆞ`chroma_db/`ᆞ`.venv/`는 **git에 없다**. 그대로 켜면 검색이 통째로 안 되거나
API 키가 없어 뜨지 않는다.

```bash
uv sync --extra dev                      # 1. 의존성(테스트 포함)

cp .env.example .env                     # 2. API 키 입력
#   GEMINI_API_KEY (필수)
#   CEREBRAS_API_KEY / VWORLD_API_KEY / VWORLD_DOMAIN / ARCHHUB_SERVICE_KEY (선택)
#   LANGCHAIN_API_KEY (선택, LangSmith 추적)

uv run python -m src.pipeline --ingest    # 3. 인덱싱 (필수! 안 하면 검색 0건)
uv run pytest                             # 4. 확인 - 200 passed 나와야 정상
uv run uvicorn src.api:app --reload       # 5. 서버
```

3번을 빠뜨리면 **에러 없이 조용히 틀린 답**이 나간다(검색이 실패하는 게 아니라 "가장
비슷한" 무관한 조문을 돌려주기 때문). 서버 시작 시 미인덱싱 경고가 뜨니 로그를 확인할 것.

첫 실행은 임베딩 모델ᆞ리랭커(약 2.3GB)를 내려받느라 몇 분 걸린다.
